# Electricity System

Electricity System — учебная микросервисная backend-система для автоматизации сбора показаний приборов учета электроэнергии в B2B-сегменте.

Проект моделирует работу личного кабинета потребителя электросбытовой компании и административного контура ЭСК. Основной фокус — проектирование предметной области, API-контрактов и взаимодействия микросервисов.

## Описание проекта

Система предназначена для автоматизации процессов:

- регистрации потребителей;
- проверки договоров энергоснабжения;
- ведения организаций и договоров;
- учета приборов электроэнергии;
- передачи показаний;
- изменения статусов переданных показаний;
- последующего аудита действий администратора.

Frontend в текущей учебной версии не является обязательной частью проекта. Демонстрация API выполняется через Swagger.

---

## Бизнес-процессы

### БП-1. Регистрация потребителя и проверка договора

Потребитель регистрируется в системе через IdentityService.

После регистрации пользователь должен загрузить скан-копию договора. Администратор проверяет документ и создает в системе организацию, договор и приборы учета.

До проверки договора пользователь не должен иметь доступ к передаче показаний.

### БП-2. Передача показаний

Потребитель передает показания по приборам учета, связанным с его договором.

Передаваемые данные:

- contractId;
- meterId;
- расчетный период;
- дневное значение;
- ночное значение;
- ссылка на фото счетчика.

В будущей реализации система должна проверять, что новые показания не меньше предыдущих.

### БП-3. Администрирование и аудит

Администратор может изменять данные договоров, приборов учета и статусы переданных показаний.

Действия администратора должны фиксироваться в журнале аудита.

## API-контракты

На текущем этапе endpoints зафиксированы как API-контракты микросервисов. Бизнес-логика будет реализована следующим этапом.

---

### IdentityService

IdentityService отвечает за пользователей, роли, регистрацию, вход и проверку доступа.

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | /api/auth/register | Регистрация нового пользователя |
| POST | /api/auth/login | Вход пользователя в систему |
| POST | /api/auth/verify-2fa | Подтверждение двухфакторной аутентификации |
| GET | /api/users/me | Получение данных текущего пользователя |
| GET | /api/users/{userId} | Получение пользователя по id |
| GET | /api/users/{userId}/access-status | Проверка статуса доступа пользователя |
| GET | /api/users | Получение списка пользователей |
| PATCH | /api/users/{userId} | Изменение контактных данных пользователя |
| PATCH | /api/users/{userId}/role | Изменение роли пользователя |
| PATCH | /api/users/{userId}/status | Изменение статуса пользователя |
| GET | /api/roles | Получение списка ролей |

---

### ContractService

ContractService отвечает за организации, договоры, приборы учета и документы.

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | /api/organizations | Создание организации |
| GET | /api/organizations/{organizationId} | Получение организации по id |
| POST | /api/contracts | Создание договора |
| GET | /api/contracts/{contractId} | Получение договора по id |
| GET | /api/users/{userId}/contracts | Получение договоров пользователя |
| PATCH | /api/contracts/{contractId}/status | Изменение статуса договора |
| POST | /api/contracts/{contractId}/meters | Добавление прибора учета к договору |
| GET | /api/contracts/{contractId}/meters | Получение приборов учета по договору |
| GET | /api/meters/{meterId} | Получение прибора учета по id |
| GET | /internal/meters/{meterId} | Внутренняя проверка прибора учета другими сервисами |
| POST | /api/documents | Добавление документа |
| GET | /api/contracts/{contractId}/documents | Получение документов по договору |

---

### ReadingService

ReadingService отвечает за передачу показаний, историю показаний и изменение статуса показаний.

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | /api/reading-submissions | Передача показаний пользователем |
| GET | /api/reading-submissions/{submissionId} | Получение передачи показаний по id |
| GET | /api/contracts/{contractId}/reading-submissions | Получение истории показаний по договору |
| PATCH | /api/reading-submissions/{submissionId}/status | Изменение статуса показаний администратором |

## Взаимодействие сервисов

В будущей реализации микросервисы должны взаимодействовать друг с другом через HTTP API.

Основной сценарий взаимодействия связан с передачей показаний пользователем.

### Основной сценарий

1. Пользователь проходит авторизацию через IdentityService.
2. IdentityService подтверждает личность пользователя и его статус доступа.
3. ContractService хранит договоры пользователя и связанные с ними приборы учета.
4. Пользователь отправляет показания в ReadingService.
5. ReadingService перед сохранением показаний проверяет прибор учета через ContractService.
6. Если договор и прибор учета существуют, ReadingService принимает показания.
7. Администратор позже может изменить статус показаний на Accepted или Rejected.

---

### Схема взаимодействия

text User  │  │ 1. Login / Register  ▼ IdentityService  │  │ 2. Access status  ▼ ContractService  │  │ 3. Contracts and meters  ▼ ReadingService  │  │ 4. Reading submission  ▼ Admin

---

### Пример межсервисного запроса

ReadingService должен обращаться к ContractService, чтобы проверить существование прибора учета перед сохранением показаний.

text ReadingService -> ContractService GET /internal/meters/{meterId}

Этот endpoint нужен для проверки, что:

- прибор учета существует;
- прибор учета привязан к договору;
- договор активен;
- пользователь имеет право передавать показания по этому договору.

---

### Назначение сервисов в сценарии

| Сервис | Роль в сценарии |
|---|---|
| IdentityService | Проверяет пользователя и его статус доступа |
| ContractService | Хранит договоры, организации и приборы учета |
| ReadingService | Принимает и хранит показания |
