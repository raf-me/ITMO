## Задание №1. Обмен сообщениями по UDP

Реализовать клиентскую и серверную часть приложения. Клиент отправляет серверу сообщение «Hello, server», и оно должно отобразиться на стороне сервера. В ответ сервер отправляет клиенту сообщение «Hello, client», которое должно отобразиться у клиента.

####Требования:

Обязательно использовать библиотеку socket.
Реализовать с помощью протокола UDP.


### Реализация

Созданы файлы `ServerUDP.py` и `ClientUDP.py`. Сокеты создаются с параметрами `socket.AF_INET` и `socket.SOCK_DGRAM`. Сервер связывает сокет с адресом через `bind()` и ожидает датаграммы с помощью `recvfrom(1024)`.

Метод `recvfrom()` возвращает данные и адрес отправителя. Сервер использует полученный адрес для ответа через `sendto()`. Клиент отправляет сообщение на заранее известный адрес сервера и принимает ответ. Строки кодируются в UTF-8 перед отправкой и декодируются после получения.

### Проверка и результат

Сначала запускается сервер, затем в отдельном процессе — клиент. В выполненном запуске клиент получил ответ:

```text
Ответ сервера: Hello, client!
Process finished with exit code 0
```

## Задание №2. Решение квадратного уравнения через TCP

Реализовать клиентскую и серверную часть приложения. Клиент запрашивает выполнение математической операции (`ax² + bx + c = 0`), параметры которой вводятся с клавиатуры. Сервер обрабатывает данные и возвращает результат клиенту.

####Требования:

Обязательно использовать библиотеку socket.
Реализовать с помощью протокола TCP.


### Реализация

Используются файлы `ServerTCP.py` и `ClientTCP.py`, сокеты `socket.SOCK_STREAM`. Сервер вызывает `bind()`, `listen()` и `accept()`. Клиент подключается через `connect()`.

На клиенте коэффициенты преобразуются в числа типа `float`, затем передаются одной строкой с разделителями-пробелами:

```python
message = f"{a} {b} {c}"
clientSocket.sendall(message.encode("utf-8"))
```

Сервер разбирает строку:

```python
a, b, c = map(float, request.split())
```

При `a == 0` возвращается сообщение о том, что уравнение не является квадратным. В остальных случаях вычисляется дискриминант `D = b² − 4ac`:

- `D < 0`: действительных корней нет.
- `D == 0`: один корень `x = −b / (2a)`.
- `D > 0`: два корня `x₁ = (−b + √D) / (2a)` и `x₂ = (−b − √D) / (2a)`.

Результат преобразуется в строку и возвращается клиенту. Один запуск клиента решает одно уравнение, после чего соединение закрывается. Сервер продолжает принимать подключения.

### Примеры:

| a | b | c | Ожидаемый результат |
|---|---|---|---|
| 1 | −5 | 6 | Корни 3 и 2 |
| 1 | 2 | 1 | Корень −1 |
| 1 | 0 | 1 | Действительных корней нет |
| 0 | 2 | 1 | Сообщение: уравнение не квадратное |



## Задание №3. Выдача HTML-страницы по HTTP

Реализовать серверную часть приложения. Клиент подключается к серверу и в ответ получает HTTP-сообщение, содержащее HTML-страницу, которую сервер подгружает из файла index.html.

####Требования:

Обязательно использовать библиотеку socket.


### Реализация

Созданы `serverHTML.py` и HTML-файл в `src/main/recources/ex3/`. Основной клиент — браузер. Дополнительно создан `ClientHTML.py` для просмотра HTTP-ответа в консоли.

Сервер принимает TCP-подключение, читает запрос и открывает HTML-файл в режиме `r` с кодировкой UTF-8. Содержимое преобразуется в байты. Формируется ответ:

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: <размер тела в байтах>
Connection: close

<содержимое index.html>
```

В реальном сообщении строки заголовков разделяются `\r\n`, а заголовки и тело — `\r\n\r\n`. Размер `Content-Length` вычисляется после кодирования HTML в байты, что важно для кириллицы.

Python-клиент отправляет `GET / HTTP/1.1` с заголовком `Host` и читает ответ частями до закрытия соединения. Браузер вместо вывода исходного кода отображает HTML-страницу.

### Проверка и результат

В выполненном запуске `ClientHTML.py` получил статус `200 OK`, заголовок `Content-Length: 262` и HTML со следующим содержимым:

```html
<h1>Привет от сервера!</h1>
<p>Эта страница прочитана из файла index.html.</p>
```

## Задание №4. Многопользовательский TCP-чат

Реализовать двухпользовательский или многопользовательский чат. Для максимального количества баллов реализуйте многопользовательский чат.

####Требования:

Обязательно использовать библиотеку socket.
Для многопользовательского чата необходимо использовать библиотеку threading.
Должна быть возможность идентифицировать пользователей.
Пользователь должен иметь возможность выйти из чата.

####Реализация:

Протокол TCP — 100% баллов.
Протокол UDP — 80% баллов.
Для UDP используйте threading для получения сообщений на клиенте.
Для TCP запустите обработку подключений и сообщений от всех пользователей в потоках. Не забудьте сохранять пользователей, чтобы отправлять им сообщения.


### Реализация

Созданы `serverChat.py` и один универсальный `clientChat.py`. Каждый участник запускает отдельный процесс того же клиентского файла и вводит имя. Отдельные файлы под конкретных пользователей не создаются.

Сервер принимает подключения и запускает для каждого функцию `handle_client()` в отдельном потоке. Подключения и имена хранятся в словаре `users`. Имя дополняется портом клиента, позволяющим различать участников с одинаковыми именами.

Функция `broadcast()` отправляет сообщение всем зарегистрированным клиентам, кроме отправителя. Для доступа к общему словарю используется `threading.Lock`.

На клиенте основной поток читает ввод с клавиатуры и отправляет сообщения. Отдельный поток выполняет `receive_message()`, получает сообщения сервера и выводит их в консоль.

Каждое сообщение завершается `\n`. Приём выполняется через `makefile("r", encoding="utf-8")` и `readline()`. Такое разделение позволяет читать отдельные сообщения из TCP-потока.

Команда выхода в текущей реализации — `exit`. При выходе сервер удаляет подключение из словаря, закрывает его и уведомляет остальных участников.

### Проверка и результат

Одновременно запущены два экземпляра клиента с именами Аня и Борис. Участники успешно обменялись сообщениями в обоих направлениях. После команды `exit` у Бориса Аня получила уведомление о его выходе.

## Задание №5. Веб-сервер для журнала оценок

Написать простой веб-сервер для обработки GET и POST HTTP-запросов с помощью библиотеки socket в Python. Сервер должен:

Принимать и записывать информацию о дисциплине и оценке по дисциплине.
Отдавать информацию обо всех оценках по дисциплинам в виде HTML-страницы.


### Хранение данных

Оценки представлены словарём, где ключ — название дисциплины, значение — список оценок:

```json
{
    "Математика": [5, 4, 5],
    "Физика": [4]
}
```

При запуске сервер читает словарь из `grades.json`. Если файла нет, используется пустой словарь. Для вручную созданного пустого журнала файл должен содержать `{}`, а не быть пустым.

После успешного добавления оценок обновлённый словарь записывается целиком через `json.dump()`. HTML служит шаблоном отображения, а не хранилищем оценок. Отдельный файл `server.log` содержит события сервера и сообщения об ошибках.
